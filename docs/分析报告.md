## 1. AEP 二进制结构说明

### 1.1 总体格式

`.aep` 是 QQ 音乐私有音效文件，魔数为 **`QMAEP`**，采用 **FlatBuffers 风格的自定义变体**：

- 文件以 `uoffset32`（相对自身位置的前向偏移）指向 root table；
- table 前有一个 **vtable**，以 `int32 soffset`（相对 table 位置的**有符号**偏移）定位；vtable 结构为 `u16 vtable_size, u16 object_size, u16 field_off[0..n-1]`；
- 字段偏移为 0 表示该字段缺省；
- 字符串 = `u32 长度 + UTF-8 内容 + '\0'`；
- vector = `u32 元素个数 + 元素数组`（本例元素为 uoffset）。

与标准 FlatBuffers 的差异在于：文件根部额外有一段魔数字符串字段、参数实体采用「name 字符串 + `u32 类型标签 + float32 值` 结构体」的形式，因此不能用通用 FlatBuffers 库直接读取，需按其 schema 遍历。

### 1.2 Schema（按实际文件反推并逐字节验证）

```
root table (3 fields)
  field0 -> string  "QMAEP"        (magic)
  field1 -> string  "全景环绕"      (效果名, UTF-8, 前缀 u32 长度 12)
  field2 -> vector<EffectNode>

EffectNode table (2 fields)
  field0 -> int32   node id        (标量; 13=EQ, 12/11/4=Widener 子组)
  field1 -> vector<Param>

Param table (3 fields)
  field0 -> string  name           (参数名)
  field1 -> struct{ u32 typeTag=4; float32 value }   (值在名字之前)
  field2 -> string  unit / 备用 (本文件恒为空串)
```

### 1.3 关键 hex 片段

文件头 + 根表（root table @ 0x10，其 vtable @ 0x06）：

```

0010  0a 00 00 00 0c 00 00 00 1c 00 00 00 2c 00 00 00   <- root soffset=10; f2->0x20(vector), f1->0x34, f0->0x48
0020  04 00 00 00 e8 04 00 00 48 04 00 00 10 03 00 00   <- vector 长度 4, 4 个 uoffset
0030  30 00 00 00 0c 00 00 00 e5 85 a8 e6 99 af e7 8e   <- elem[3]->0x60
0040  af e7 bb 95 00 00 00 00 05 00 00 00 51 4d 41 45   <- "全景环绕"(UTF-8) + len=5
0050  50 00 00 00 ...                                    <- "QMAEP"
```

效果名与魔数：

```

```

```
00C4  04 00 00 00 00 00 00 40                           <- typeTag=4 ; float32 0x40000000 = 2.0

```


Gain 节点（本文件比旧版多出的节点，值 ≈2.2789）：

```

0530  0a 00 00 00 ... 0548: 04 00 00 00 f4 d8 11 40       <- 0x4011D8F4 = 2.27887
0550  04 00 00 00 47 61 69 6e                            <- "Gain"
```

### 1.4 解析方法

`parse_aep.py` 实现了一个 schema 感知的结构解析器（非暴力扫描）：

1. 读 `u32 @0` 得 root table；解析其 vtable，取 3 个字段；
2. field0 → magic 字符串，field1 → 效果名字符串，field2 → `vector<EffectNode>`；
3. 每个 EffectNode：field0 为标量 `int32` id，field1 为 `vector<Param>`；
4. 每个 Param：field0 → name 字符串，field1 → `u32 typeTag + float32` 值，field2 → unit 字符串；
5. 按参数名（`"NNNN Hz"`、`"Q"` 与其余）分类，记录每个字段的文件内偏移；
6. 断言关键值（magic / name / 10 段增益 / Q / 7 个 Widener 参数），失败即 `exit(1)`。

运行结果（自检通过）：

```
[i] magic = QMAEP (offset 0x48)
[i] name  = 全景环绕 (offset 0x34)
[i] nodes = [(4,['Gain']), (11,['Width','Center']), (12,['Left Time','Right Time','Left Feedback','Right Feedback']),
             (13,['Q','31 Hz',...,'16000 Hz'])]
[OK] self-check passed: all values match reference.
```

## 3. EQ 单位 = dB 的证据

1. **QQ 二进制内存在 `dBgain` 字段名**：在本工作区本地文件
   `D:\AI-Agent\ZCode\workspace\QQMusic去exe版\QQMusic.dll`（11.98 MB）中检索到 ASCII 字符串 `dBgain`，
   其邻近还有 `Channel`、`NN_Num` 等参数键，说明 QQ 音效模块以带 `dB` 前缀的键来标注增益参数。
   复现命令：`python -c "print(b'dBgain' in open(r'D:\AI-Agent\ZCode\workspace\QQMusic去exe版\QQMusic.dll','rb').read())"`（输出 `True`）。
   （上游对应文件为 `audioeffect-qm/_dev/sample/QQMusic.dll`，本地路径即上述「QQMusic去exe版」。）
2. **官方耳机校正曲线（`headphone.json`）为 dB EQ 曲线**：本地文件
   `D:\AI-Agent\ZCode\workspace\QQMusic去exe版\resae\headphone\headphone.json` 中每条耳机的 `modelEQ`
   直接给出 10 元素数组，例如 `K240` 的 `[6.3, 3.8, 2.1, 0.2, -1, -0.3, 1.8, 2.7, 0.2, 0.2]`，
   含负数与小数，是典型的 dB 增益量纲，且正好是 10 段，与「全景环绕」的 10 段 EQ 同构。
   （上游同源文件为 `audioeffect-qm/resae/headphone.csv`，本地以 JSON 形式保存于上述路径。）
3. **兄弟项目 `audioeffect-ncm` 的参数表**：`_dev/demo/_params.csv` 中网易云音效的 `eqs` 字段形如 `[-1, -1, -2, -3, -2, -2, -1, -1, -1, -1]`、`[5.6, 5.09, 2, 0.5, -2, 1.2, 3.79, 0.5, 1.5, 4]`，同样为 10 段、含负数小数的 dB 量级曲线（该文件亦为 `audioeffect-ncm` 官方的「Parameter Table」）。
4. **数值特征自洽**：本文件 10 段增益范为 `0.0 ~ 2.0`，量级小、全部非负，符合「小幅提亮的 EQ 预设」；若单位是线性倍率，`0.0` 将代表「静音该频段」，显然不成立。

结论：EQ 段值单位为 **dB**，可直接映射到 V4A `equalizer.bands`（其 range 为 -12.0..12.0 dB）。

## 4. 效果映射决策与依据

> DSP 源码来自 `ViPERFX_RE-dev` 的子模块 `ViPERDSP`（`.gitmodules` 指向
> `https://github.com/likelikeslike/ViPERDSP.git`；本地子模块为空目录，故按该 URL 的 `master`
> 分支取源，下列行号均以该方法取得的源码为准）。

### 4.1 EQ → `equalizer.bands`（直接照抄）

- **频率完全一致**：`ViPERDSP/viper/utils/MinPhaseIIRCoeffs.cpp:4-6` 的 10 段固定频率表为
  `31.0, 62.0, 125.0, 250.0, 500.0, 1000.0, 2000.0, 4000.0, 8000.0, 16000.0`（Hz），
  与 QQ 的 31/63/125/250/500/1k/2k/4k/8k/16k 完全对应（63 与 62 为同一倍频程中心，见 §6）。
- **信号链位置**：QQ 的效果链中 EQ 位于环绕级之前（未引入串扰/延迟），因此可逐段照抄为
  `equalizer.bands = [0,1,1,0,0,1,1,1,2,2]`（升序），`enable=true`。
- **Q 无法映射**：QQ 的 EQ 向量额外带一个 `Q=√1.5≈1.2247`，但 V4A 的 10 段 EQ 是**固定 Q 的最小相位 IIR**（`MinPhaseIIRCoeffs` 只按频段生成系数，无 Q 入参），因此该 Q 值**不映射**，在预设中忽略。

### 4.2 Width=130% / Center=100% → `stereoImager`（数学上精确）

- **V4A DSP 事实**：`ViPERDSP/viper/effects/StereoImager.cpp:60-65`
  ```
  const float mid  = (f_l + f_r) * 0.5f;
  float side       = (f_l - f_r) * 0.5f;
  side *= band_widths_[b];          // 只缩放 side
  out_l = mid + side;  out_r = mid - side;
  ```
  即 width 仅对 side 分量乘系数、mid 完全不动。取 `width = 1.3` 即「side +30%、mid 不变」，与
  QQ 「Width=130% + Center=100%」的定义**数学上精确等价**（QQ 的 Center 即中置能量，100% 表示不变）。
- 故三个频段全部取 `lowWidth = midWidth = highWidth = 1.3`（例：`lowCrossover=200`、`highCrossover=4000`
  沿用默认，不影响该等价性）。
- **DLL 逆向互证**：反汇编 QQ 引擎 `qmcpcom.dll` 中 StereoEnhancer（id=11）的 Process（x86 `0x1012ed60`）
  得到与上述完全一致的纯 mid/side 矩阵：`mid=(L+R)/2, side=(L-R)/2, L'=C·mid+W·side, R'=C·mid−W·side`，
  其中 `C=Center/100`、`W=Width/100`（常数 0.5 与 100.0 均在 .rdata 可见），无滤波、无延迟——
  `Width=130 → W=1.3` 与本映射逐字对应，代入即 `L'=1.15L−0.15R`（side×1.3、mid×1.0）。

**否决方案：`fieldSurround`**。`ViPERDSP/viper/utils/Stereo3DSurround.cpp:52-65`
```
tmp = stereo_widen_ + 1.0f;  x = tmp + 1.0f;  y = (x < 2 ? 0.5 : 1/x);
coeff_left  = middle_image_ * y;      // 中置系数
coeff_right = tmp * y;                // 侧向系数
```
它把左右信号做 `a=coeff_left*(L+R)`、`b=coeff_right*(R-L)` 的 mid/side 矩阵再重组，
侧/中比 = `(w+1)/m`。要凑 130% 需 `(w+1)/m = 1.3`：取 `w=0.8, m=1.4` 得
`coeff_left=0.5`、`coeff_right=0.642857`，比值 **128.6%**，只能**近似**；
且该路径还会再经过 `DepthSurround`（`ViPERDSP/viper/utils/DepthSurround.cpp`，含双一阶延迟反馈结构，会引入相位/梳状染色）。
因此否决，改用 `stereoImager` 的精确实现。

### 4.3 Left Time=0 / Right Time=26.12 ms / Feedback=0 → `diffSurround`

- **V4A DSP 事实**（`ViPERDSP/viper/effects/DiffSurround.cpp`）：
  - 延迟单位是 ms：`delay_samples = delay_time_ / 1000.0 * sampling_rate_`（`:63-64`）；
  - `reverse_` 决定延迟哪一路：`delayed_ch = reverse_ ? 0 : 1;`（`:36`），默认 `reverse=false` 时
    **延迟右路（channel 1）**，与 QQ「Left Time=0、Right Time=26.12、只延迟右路」一致；
  - `wet_dry_mix_`（`:31-34, :38-51`）实现干湿混合；取 1.0 且 `lp_cutoff=0` 时输出即纯延迟信号；
  - **无反馈级**：`Process()` 全程不含反馈路径，与 QQ「Feedback=0」一致。
- **映射**：`diffSurround = {enable:true, delay:20.0, reverse:false, wetDryMix:1.0, lpCutoff:0}`。
- **26.12 → 20 的近似**：app 侧 `EffectGroups.kt:791-799` 对 `diffSurround.delay` 定义为 range `1.0f..20.0f`，
  导入时 `EffectPrefs.kt:564-565` 会 `clamp` 到上限，故**写成 20.0（上限）**，是 26.12 ms 在普通导入流程下的最接近值，听感上差异极小（约 6 ms 的延迟缩短，主要影响声像宽度感而非音色）。
- **如需精确 26.12 ms**：`ViPERDSP` 驱动层 `SetDelayTime` 并不钳制（`DiffSurround.cpp:89-94`），可通过
  `setParameter` 直发或 full-params 通道写入精确值；普通用户不建议（超出 app 的合法范围）。本次预设取 20 ms。
- **DLL 逆向互证**：QQ 引擎 Delay 插件（id=12，x86 DSP `0x10187330`）为 `samples = Time(ms)/1000·采样率`
  （26.1224 ms @44.1 kHz = 恰好 1152 样本 = 一个 MP3 帧，显系按帧设计）、`Feedback/100` 回灌、
  **延迟支路 100% 湿声输出且不做任何滤波**（无低通/全通）——这与 `wetDryMix=1.0、lpCutoff=0` 的取值
  精确对应，也排除了"延迟支路隐藏滤波"的可能。

### 4.4 Gain=+2.27887 dB → `masterLimiter.outputVolume = 1.3`

- Gain 是 **1372 B 新版**才追加的增益节点（旧版 1276 B 无此节点、音效依然成立，见 §1.5）。
- **量纲已通过 DLL 逆向确认（先前"二义"的结论被推翻）**：QQ 引擎 Gain 插件（id=4，`AmplifierEffect`）
  的参数设置路径存在转换函数 `linear = pow(10, G/20)`（x86 `0x101006f0`），参数描述块的范围为
  `[-96, +18]`（dB 量纲的典型区间；若为线性倍率该区间无意义），处理级再做线性乘——即
  **参数是 dB**。`10^(2.27887/20) = 1.29999…`，即 QQ 作者取的正是 **×1.3 的补偿增益**。
- **映射**：`masterLimiter.outputVolume = 1.3`（V4A range 0.01..2.0 内）。
- **等价性**：QQ 链为 `Amp → StereoEnhancer → Delay → IirEQ10 → Limiter(固定追加)`，除末级限幅器外
  全为线性级，增益位置可交换；V4A 的 `outputVolume` 同样作用在末级 SoftwareLimiter 之前
  （`ViPERDSP` 的 `frame_scale_`），两端都是"增益→限幅"收尾，结构等价。且 V4A 的
  `masterLimiter.threshold=1.0`（满幅限幅）正好对应 QQ 链尾被无条件追加的 `LimiterEffect`。

### 4.5 其他否决项

- **`reverb`（否决）**：V4A 混响由 `Reverberation` → `CRevModel`（Freeverb 系数的梳状/全通网络，
  见 `ViPERDSP/viper/effects/Reverberation.h:3,23`）构成，必然会引入反射尾；而 QQ 该音效 `Feedback=0`，
  本身不含混响成分。映射 reverb 反而会「加尾」，故否决。
- **`cure` / `headphoneSurround`（否决）**：二者依赖 VHE 固定卷积核（不可调参数），无法表达 QQ 的参数语义。
- **`convolver` 自定义 kernel（否决）**：用一段 26.1224 ms 的 IR 理论上可精确复现延迟，但需要额外提供
  `.wav` 内核（普通导入预设不会带上内核），且 V4A 内核上传是另一套三段式协议，超出「单 JSON 导入」流程。

### 5.1 加载逻辑与实际处理链

- 入口：`qmcpcom_ss_load_aep_set_params` → `ss_mgr::set_effect` → `ss_op::set_aep_effect`
  （整读文件）→ `ss_op::set_params` → 按 EffectNode 的 type id `create_effect` 逐节点入链。
- 从 RTTI 还原出 **76 项插件注册表**（id→类名），本预设涉及：
  `4=Amplifier`、`6=Limiter`、`11=StereoEnhancer`、`12=Delay`、`13=IirEQ10`。
- **关键发现：链 = .aep 节点序列 + 链尾无条件追加的固定 `LimiterEffect`(id=6)**
  （`ss_op::set_params` 内硬编码）。即全景环绕的实际链：
  **Amp(4) → StereoEnhancer(11) → Delay(12) → IirEQ10(13) → Limiter(6)**。
- `QQMusic.dll` 只负责下载/缓存/导入/魔数校验，不做节点解析。

### 5.2 是否存在参数之外的隐藏处理？——没有

| 疑点 | 结论 | 证据 |
|---|---|---|
| StereoEnhancer 是否纯矩阵 | 是，纯 mid/side，无滤波无延迟 | Process `0x1012ed60`（x86），常数 0.5/100.0 |
| 延迟支路是否被滤波 | **完全不滤波**，100% 湿声 | Delay DSP `0x10187330`，无低通/全通分支 |
| EQ 有无隐藏 preamp/HP/LP | 无；Regalia-Mitra peaking×10，Q=参数值，\|gain\|<0.001 旁路 | `IirEQ10Effect`，频段表 `0x10230c60`（31.25/62.5/…/16000 Hz） |
| 官方宣传的 "ATF 增强算法" | **DLL 中不存在 ATF 模块**（仅命中 "PL-ATF-ORM"=PLATFORM），属营销话术 | 全量 ASCII/UTF-16 字符串检索 |
| CrossCancellation/HRTF/SoundField 等 | 存在但属于其他插件/API，本预设未调用 | 插件注册表 + 节点 id 比对 |
| 全局固定后级（抖动/重采样/响度归一） | 无（仅引擎级重采样与链尾限幅器） | `ss_op::set_params` 全路径核对 |

**结论：全景环绕 = EQ(10 段，dB) + mid/side 宽度(Center/Width) + 单边 Haas 延迟(Time/Feedback)
+ 输出增益(dB) + 限幅器，全部由 .aep 参数驱动，无隐藏处理。** 这使得本预设的映射可以从
"近似推断"升级为"逐级复刻"，唯一无法精确表达的是 26.12 ms 延迟被 app 钳到 20 ms。

### 5.3 设计细节佐证

- `Right Time = 26.1224 ms @44.1 kHz = 恰好 1152 样本 = 一个 MP3 帧`——延迟量按音频帧设计，
  Haas 加宽意图明确；
- `Gain = +2.27887 dB = 20·log10(1.3)`——作者按 ×1.3 整数增益取值；
- EQ 频段表实为 `31.25/62.5/125/…/16000 Hz` 标准倍频程中心，与 V4A 的 `31/62/125/…` 同源。

## 6. 导入操作步骤（ViPER4Android）

1. 将 `presets/QQ音乐-全景环绕.json` 拷贝到手机存储任意位置（保持 **`.json` 扩展名**）。
2. 打开 V4A app → 进入 **设置（Settings）对话框** → **Import preset（导入预设）**。
3. 系统文件选择器会以 **MIME `application/json`** 过滤（见 `MainScreen.kt:230`），选中该 `.json`。
4. **单文件导入立即生效**：`importPresetFiles` 在成功导入 1 个文件后直接套用并下发全量状态
   （`MainViewModel.kt:1197` 起，`total==1 && count==1` 分支）；预设同时保存到
   **`Android/data/com.llsl.viper4android/files/Preset/`**
   （`getExternalFilesDir(null)/Preset`，包名 `com.llsl.viper4android`）。
5. **注意总开关**：`masterEnable` **不属于** 预设内容（`EFFECT_GROUPS` 中不含它，见 `EffectGroups.kt:1311-1337`
   与 `Effects.masterEnable`），导入后需**手动打开 app 顶部总开关**，效果才会实际生效。

## 7. 已知局限与可调建议

| 项 | 说明 | 建议 |
|---|---|---|
| Right Time 26.12 ms → 20 ms | app `diffSurround.delay` range 为 1..20 ms，导入时被钳制 | **唯一实质近似**；听感差异小，如需精确可用驱动层 `setParameter` 直发（不推荐普通用户） |
| Gain=+2.27887 dB | 已确认 dB 语义并映射为 `outputVolume=1.3`（DLL 逆向） | 无需处理；嫌响可自行回调 |
| Q=1.2247 未映射 | V4A 10 段 EQ 为固定 Q 最小相位 IIR，无 Q 入参 | 无法表达；对本例（宽带提升）影响有限 |
| 63 Hz vs 62 Hz | QQ 频段表实为 31.25/62.5/…（§5.3），与 V4A 的 31/62/… 同一标准中心 | 同一档，直接对应，无需处理 |
| 未映射的环绕「深度/反馈」 | QQ 该音效 Feedback 均为 0，无额外深度参数 | 无需映射 |
