# QQ 音乐音效引擎（qmcpcomx64.dll）加载逻辑静态分析

- 目标：`D:\AI-Agent\ZCode\workspace\QQMusic去exe版\qmcpcomx64.dll`（x64，2.1 MB）
- 对照：`qmcpcom.dll`（x86，2.9 MB）、`QQMusic.dll`（x86，主程序，12 MB）
- 样本：`resae\recommendbase\*.aep`（共 50 个，含 `500-全景环绕.aep`）

## 0. 结论摘要

1. **解析入口**：`.aep` 是带 `"QMAEP"` 魔数标签的 FlatBuffers 变体。魔数在 x64 里被写进两个
   `std::string` 全局（`0x1801f2c90` / `0x1801f2cb0`，静态初始化器 `0x180001c70`/`0x180001cd0`）。
   解析链：`qmcpcom_ss_set_effect`/`set_params` 系列导出 → `ss_mgr::set_effect`(`0x18006b840`) →
   读文件 → `ss_op::set_params`(`0x180071530`) → 对每个数据块调用 `0x18008f380` →
   `0x1800758c0` → schema 子解析器 `0x1800759b0` 校验魔数、按节点 type id 逐个
   `create_effect`(`0x18008e010`)；另有 `ss_op::init_audio_effect`(`0x18006fa80`) 解析"report string + flatbuffer"。
2. **插件注册表**：`create_effect` → `0x180099ec0` 内是一张 **76 项跳转表**（表 VA `0x18009ab1c`，
   覆盖 id 1..76），每个 case = `operator new(size)` + 构造函数；由 vtable RTTI 还原出完整
   **id → 类名** 表（见 §2，全部 76 项，`effect_registry.json`）。引擎为"超重低音/SuperSound2"系，含
   EQ、卷积、混响、HRTF、声场、虚拟低音、人声分离、压限器等。
3. **链组装**：链上节点**严格来自 `.aep`**（按文件顺序逐节点建立），**但在链尾会无条件追加一个
   固定的 LimiterEffect（type id=6）**：`ss_op::set_params` 在 `0x18007188c` 处
   `lea ecx,[rbx+6]; call 0x18008e010`（创建 6 号限幅器）并放到数组末尾，
   随后 `0x1800718d1` 调用 `supersound_params2stream`(`0x18008e4c0`) 送入引擎。
   → 对"全景环绕"这类推荐音效，运行时链 = **Amp(4) → StereoEnhancer(11) → Delay(12) → EQ10(13) → Limiter(6)**。
4. **Gain 节点(id=4)**：是链中的一级 `AmplifierEffect@AMPLIFIER`（非全局总输出特殊节点）。
   参数 `Gain` 存到对象 `+0x6f8`，处理时 **`mulss` 线性相乘**（`0x1800b1150`），即 2.27887 是**线性倍数**（≈ +7.15 dB），非 dB 值。
5. **QQMusic.dll 里的 "QMAEP"**：构造一个全局 `std::string("QMAEP")`（初始化器 `0x10006530`，
   全局 `0x10ae13c0`），有 5~6 处把它用作字符串比较（校验魔数）。周围字符串
   (`AudioEffect.qmaep`、`SSN\CustomAep\`、`customAep.ini`、`.aepk`、`AddLocalAEPFile`) 表明它负责
   **本地 AEP 文件的下载/缓存/导入/命名与魔数校验**；QQMusic.dll 导入并调用 `qmcpcom.dll`
   的 32 个 `qmcpcom_ss_*` 接口（`qmcpcom_ss_params2stream`/`stream2params`/`set_params` 等），
   **不包含** 效果类名/工厂/`create_effect`/`SUPERSOUND2` 任何符号 → **不做节点图解析**，只透传。

## 1. 解析入口（问题 1）

### 1.1 魔数常量位置

- `"QMAEP"` 字符串：文件偏移 `0x193bd4` → VA **`0x1801949d4`**（`.rdata`）。
- 交叉引用只有 2 处，均为**静态初始化器**（把 "QMAEP" 构造进全局 `std::string`）：

```
0x180001c70: sub rsp,0x28
0x180001c74: lea rcx,[rip+0x1f1015]      ; 目标全局 std::string = 0x1801f2c90
0x180001c7b: call 0x180018d20            ; std::string::string()（默认构造）
0x180001c86: mov qword ptr [rip+0x1f1017],0xf
0x180001c91: lea rdx,[rip+0x192d3c]      ; "QMAEP"  (=0x1801949d4)
0x180001c98: mov qword ptr [rip+0x1f0ffd],0
0x180001ca3: lea rcx,[rip+0x1f0fe6]
0x180001cb1: call 0x18001e2e0            ; std::string::assign(全局, "QMAEP", 5)
```
第二个初始化器 `0x180001cd0` 同理写入全局 **`0x1801f2cb0`**（`r8d=5`）。
→ 存在两个内容相同的 `"QMAEP"` 强度量全局（典型：两个 translation unit 各有一份 `static const std::string`）。

### 1.2 读取/校验魔数（反序列化侧）

`0x1800759b0` 是 schema 子解析器，它从输入 flatbuffer 里取出一个字符串，与全局 `0x1801f2cb0` 比较：

```
0x180075b0c: call 0x18001e2e0            ; 构造 std::string(解析出的字段)
0x180075b11: lea rdx,[rip+0x17d198]      ; = 0x180192cb0 = &全局"QMAEP"
0x180075b18: cmp qword ptr [rip+0x17d1a8],0x10   ; std::string 容量>=16? (SSO 判定)
0x180075b20: cmovae rdx,[rip+0x17d188]   ; 若堆分配则取 data 指针
0x180075b28: mov rcx,rdi
0x180075b2b: call 0x180052920            ; std::string 比较 (== "QMAEP")
0x180075b30: test eax,eax
0x180075b32: jne 0x180075ebd              ; 不等 -> 失败返回
```
比较通过后，紧接着（`0x180075be0` 起）遍历一个 vector，对每个元素先经 `0x18006e090` 定位子表、
再读其 **type id 字段**，然后：

```
0x180075bf5: movsxd rax,dword ptr [r15]   ; flatbuffer vtable soffset
0x180075bf8: mov rcx,r15
0x180075bfb: sub rcx,rax                   ; rcx = vtable
0x180075bfe: cmp r14w, word ptr [rcx]      ; idx < vtable_size ?
0x180075c04: movzx eax, word ptr [rcx+4]   ; 字段 0 偏移
0x180075c10: mov ecx, dword ptr [rax+r15]  ; 读出 type id
0x180075c18: lea rdx,[rbp-0x51]
0x180075c1c: call 0x18008e010              ; create_effect(type_id) -> 实例
0x180075c21: cmp qword ptr [rbp-0x51],0   ; 失败则跳过
0x180075c34: call 0x1800523d0              ; push_back 到链容器
```
→ **每读到一个 EffectNode 就按 type id 实例化一个效果对象并 push 进链**（同构节点可重复出现，见 §2 的 `(3,3,11,5,3,3,9,11,3,3)` 组合）。

### 1.3 文件→内存的解析流程

- 导出 `qmcpcom_ss_load_aep_set_params`（RVA `0x1cb00`）是 .aep 加载的公开入口；`qmcpcom_ss_set_params`
  （RVA `0x1c920`）等亦触发同一路径。
- `ss_mgr::set_effect`（`0x18006b840`，含日志 `"ss_op::set_aep_effect: type = %d, effect_param_len = %d"`）
  按 type 分派；aep 分支经 `ss_op::set_aep_effect`（`0x18006ec80`）用函数指针 `rfunc_file_open/
  rfunc_file_get_size/rfunc_file_read` 读入整文件（对应日志 `"ss_op::set_aep_effect: rfunc_file_* failed"`）。
- `ss_mgr::cfunc_get_aep_config`（`0x18006c690`）在读完文件后调用 `ss_op::set_params`（`0x180071530`，见 §3）。
- 另一条路径 `ss_op::init_audio_effect`（`0x18006fa80`）：
  ```
  0x18006fb11 构造 report string(来自 ae_init_info[0]) 与 flatbuffer(ae_init_info[0x10])
  0x18006fc81  日志 "report string is empty -> 0x7d1"
  0x18006fcb1  日志 "report string = %s, flatbuffer length = %d"
  0x18006fcc7  call 0x1800704c0        ; 解析 report string（基于 Json，产出 vector<std::string>）
  0x18006fd06  call 0x18008f380        ; 解析 flatbuffer(二进制 .aep)
  异常 funclet 0x180161a19 日志 "ss_op::init_audio_effect flatbuffer decode exception!!!"（错误码 0x7e9）
  ```
- Flatbuffer 解码封装 `0x18008f380(out_vec, out_cnt, data, len)`：
  ```
  0x18008f425  call 0x1800758c0        ; 真正的 schema 解析，填充 vector
  0x18008f432-0x18008f489 把 vector 内容复制成 8 字节指针数组（每元素一个效果对象指针）
  ```
- 核心解析器 `0x1800758c0` 依次调用 4 个 schema 子解析器（`0x1800759b0` / `0x1800763d0` /
  `0x180075ef0` / `0x1800768b0`），任一失败即整体失败；其中至少 3 个会对读到的 type id 调
  `create_effect`（分别在 `0x180075c1c`、`0x1800760fe`、`0x1800765de`）。

> 与既有 `parse_aep.py` 的结论一致：root 3 字段 = `magic("QMAEP")`、`name`、`vector<EffectNode>`；
> 本分析补上了引擎侧"魔数校验 + 逐节点实例化"的代码证据。

## 2. 插件注册表（问题 2）

`create_effect` 的内部实现 `0x18008e010(type, out)`：

```
0x18008e01f: call 0x18009ad10            ; 取管理器单例
0x18008e029: call 0x180099ec0            ; Manager::CreateByType(type)
0x18008e034: jne 0x18008e049
0x18008e039: mov eax,0x3e9               ; 未找到 -> 错误 1001
0x18008e049: mov rax,[rax]
0x18008e04c: call qword ptr [rax+0x28]   ; 虚函数 Create()/Clone()
```

`0x180099ec0` 是一个 **switch 派发**：

```
0x180099ed8: dec edx                     ; edx = type
0x180099eda: cmp edx,0x4b                ; type-1 ∈ [0,0x4b] 即 type ∈ [1,76]
0x180099ee6: lea rdx,[rip-0x99eed]       ; rdx = ImageBase 0x180000000
0x180099eed: mov ecx,[rdx+rax*4+0x9ab1c] ; 跳转表 @ VA 0x18009ab1c
0x180099ef4: add rcx,rdx
0x180099ef7: jmp rcx
```
每个 case 形如（以 id=11 为例）：
```
0x18009a09d: lea rdx,[...]  ; 源文件/RTTI 标签指针
             mov ecx,0x708 ; 对象大小
             call 0x1801568a0   ; operator new
             call 0x1800b3e70   ; StereoEnhancerEffect 构造函数
```
构造函数里 `mov dword ptr [rbx+0x44],<type>` 会把自身 type id 写进对象 `+0x44`（如 id11 的
`0x1800b3ea7: mov dword ptr [rbx+0x44],0xb`）。

### 2.2 参数注册机制（参数名从哪来）

每个效果类的构造函数/初始化方法通过 **`0x1800ad120(obj, 参数名, 语言, 显示名)`** 注册参数字段，
另有 `0x1800ad5e0` 注册本地化效果名。示例（StereoEnhancerEffect，id=11）：

```
0x1800b3f74: lea r9,[rip+0xbe93d]
0x1800b3f7b: lea r8,[rip+0xdf8ea]   ; "zh"
0x1800b3f82: lea rdx,[rip+0xbe61f]  ; "Width"
0x1800b3f8c: call 0x1800ad120
0x1800b3fb3: lea r8,[rip+0xdf8b2]   ; "zh"
0x1800b3fba: lea rdx,[rip+0xbe5ef]  ; "Center"
0x1800b3fc4: call 0x1800ad120
```
这也解释了 `.aep` 的 `Param.name` 为什么是可读字符串（"Gain"、"Width"、"Left Time"…）——
它们就是各效果注册的字段名，反序列化时按名字回填。全库共 **232 处** `call 0x1800ad120`，
分布在 `0x1800af000`~`0x1800e0000` 的效果类构造函数区。

## 3. 链的组装与固定处理节点（问题 3）

### 3.1 链节点 = .aep 节点 + 固定尾节点限幅器

`ss_op::set_params`（`0x180071530`）：

1. 取 `m_vec_effect_items`（每项 `0x18` 字节：`[dword+0 flags/type][dword+4 subtype][qword+8 data][dword+0x10 len]`），
   日志 `"ss_op::set_params: m_vec_effect_items.size = %d"`。对其中 dword0==1 且 subtype∈{0x3e,0x327}
   的项做重排/删除特判（`0x180071600`~`0x1800716b3`）。
2. 逐项解码其内嵌二进制（即 .aep 数据）：`0x1800717c5: call 0x18008f380`，得到的是一批**效果对象指针**，
   再 `push_back` 进临时数组（`0x1800717e0`）。type==0x20 的项被跳过。
3. 统计临时数组元素数 `ebx`。**若非 0，则分配 `count+1` 个槽并追加一个 Limiter**：

```
0x180071835: mov r13d,ebx                ; r13d = 效果数量
0x180071838: test ebx,ebx
0x18007183a: je   0x1800718a5            ; 没有效果 -> 不加限幅器
0x18007183c: lea  r13d,[rbx+1]           ; 数组长度 = 数量+1
... 复制已有效果指针 ...
0x180071882: xor  ebx,ebx
0x180071888: lea  rdx,[rbp-0x51]
0x18007188c: lea  ecx,[rbx+6]            ; ecx = 6  == LimiterEffect
0x18007188f: call 0x18008e010            ; create_effect(6)
0x180071894: lea  eax,[r13-1]            ; 索引 = count
0x18007189f: mov  qword ptr [rdi+rcx*8],rax  ; 追加到链尾
```
4. 把这个"效果数组 + 限幅器"交给引擎：
```
0x1800718c6: mov  r8,rdi
0x1800718c9: lea  rdx,[rbp-0x49]         ; out_count
0x1800718d1: call 0x18008e4c0            ; supersound_params2stream
0x1800718d8: jne  "ss_op::set_params supersound_params2stream failed!!!"
```

→ **结论：处理链不是纯粹等于 .aep 节点，链尾被无条件追加了一个固定的 `LimiterEffect`（type id=6）。**
对 `500-全景环绕.aep`（节点序 4,11,12,13）实际链为：
`AmplifierEffect(4) → StereoEnhancerEffect(11) → DelayEffect(12) → IirEQ10Effect(13) → LimiterEffect(6)`。

### 3.2 校验：其他硬编码 type id 的实例化点（均**不属于**常规 .aep 链）

对所有 `call 0x18008e010` 的立即数进行了枚举，固定 id 只出现在以下几处，且各属独立功能：

| 位置 | id | 所属函数 | 用途 |
|------|----|----------|------|
| `0x18007188f` | 6 (Limiter) | `ss_op::set_params` 0x180071530 | **链尾固定限幅器**（见上）|
| `0x18006f082` | 0x40=64 RoomEQ | `0x18006efb0` | 车机/RoomEQ 专用配置组装 |
| `0x18006f2e8`…`0x18006f5e7` | 0x31/0x18,0xe,0x10,0xf,0x13,0x1a | `ss_op::set_eq_effect` 0x18006f1c0 | 依"eq_effect_list"**数据驱动**建 EQ 链（非固定）|
| `0x1800723d4` | 0x3d=61 HandDraw3DIRBased | `0x180072090` | 旧版 HRTF 配置→新效果的一次性迁移 |
| `0x180075c1c`/`0x1800760fe`/`0x1800765de` | 动态 | schema 子解析器 | **按 .aep 节点 type id 建链**（主路径）|

除 Limiter 外，未发现常规 aep 链上被无条件追加的其它固定节点（如重采样/抖动/淡入淡出/响度归一）。
`ResamplerEffect(10)`、`ExciterEffect(9)` 等只以"节点 id"形式存在于注册表中，仅当 .aep 显式包含时才入链。
`"outputGain"` / `"limiterEnable"` / `"limiter enable"` 等字符串是 `agc_effect`/`compressor_effect` 内部字段，
不是全局总输出节点（其注册点分别在 `0x1800d7xxx`~`0x1800d88xx` 的这两个效果类内）。

## 4. Gain 节点（id=4）的角色（问题 4）

- id=4 对应 **`AmplifierEffect@AMPLIFIER`**（vtable `0x180171018`，构造函数 `0x1800b0f60`；
  构造函数内 `mov dword ptr [rbx+0x44],?` 写自身 type id）。
- 参数 `Gain` 的注册与存储：
```
0x1800b1043: lea rdx,[rip+0xe1a36]   ; "Gain"
0x1800b104d: call 0x1800ad120        ; 注册字段 "Gain"
...
0x1800b106e: movss dword ptr [rbx+0x6f8],xmm0   ; 把解析出的值存入对象 +0x6f8
```
- 处理时按**线性倍数**使用（`mulss`，非 dB 对数换算）：
```
0x1800b1150: mulss xmm0, dword ptr [r11+0x6f8]  ; 采样 * Gain
```
- 因此 `.aep` 中 `Gain=2.27887` 是**线性幅度系数**（≈ +7.15 dB），不是 2.28 dB。
- 它是链中普通一级（可与其他节点任意排列），**不是全局输出级**；在推荐音效里常与 StudioIr(2)
  成组出现（见 preset 组合 `(2,4)`×5、`(2,9,4)`…），作用是补偿 IR/卷积的增益。

## 5. QQMusic.dll 中那处 "QMAEP"（问题 5）

- 文件偏移 `0x8e8ee0` → VA **`0x108ea0e0`**，唯一一处，前后紧邻 "Unknown exception"/"bad cast" 等运行时字符串。
- 该字符串被一个**静态初始化器**用来构造全局 `std::string`（全局对象 `0x10ae13c0`）：
```
0x10006530: push 5
0x10006532: push 0x108ea0e0      ; "QMAEP"
0x10006537: mov  ecx,0x10ae13c0
0x1000653c: call 0x1002be90      ; std::string 构造(全局, "QMAEP", 5)
```
- 有 5~6 处把该全局用于字符串比较（校验魔数），例如：
```
0x100829d4: cmp  dword ptr [0x10ae13d4],0x10   ; std::string SSO 判定
0x100829db: mov  eax,0x10ae13c0
0x100829e6: cmovae eax,[0x10ae13c0]
...
0x10082a02: call 0x10032d80                    ; 比较
0x10082a15: setne byte ptr [ebp-0x55]          ; == "QMAEP" ? bool
```
- 周边字符串（UTF-16）：`AudioEffect.qmaep`、`SSN\CustomAep\`、`customAep.ini`、`AepInfo`、`.qmaep`、`.aepk`、
  `.aep`、`AddLocalAEPFile`、以及模板 `{"aepEdit":{"name":"%s","param":"%s","uin":"%lld"}}`。
- QQMusic.dll 导入表只导入 **`qmcpcom.dll`** 的 `qmcpcom_ss_*` 接口（32 个，如
  `qmcpcom_ss_params2stream` / `qmcpcom_ss_stream2params` / `qmcpcom_ss_set_params` / `qmcpcom_ss_add_effect`）。
- 全文搜索：QQMusic.dll 中 **没有** `ss_op::` / `create_effect` / `SUPERSOUND2` / `StereoEnhancer` / `EffectNode`
  等引擎符号（`qmcpcom_ss` 出现的 32 处全是导入名）。

→ **判断：QQMusic.dll 只是 AEP 的"文件与业务层"**——管理下载/缓存目录（`CustomAep`）、本地/自定义 AEP 导入
（`AddLocalAEPFile`）、命名与编辑元数据，并用 `"QMAEP"` 魔数做**文件类型校验**；真正的 flatbuffer 节点解析、
效果实例化与 DSP 全部委托给 `qmcpcom.dll`/`qmcpcomx64.dll`。**不参与节点图解析。**

## 6. 方法与可复现性

- 字符串/节区/导出：`strings -a -t x`、`objdump -p`、`pefile`。
- 定位魔数引用：先用 `capstone` 线性反汇编扫 rip 相对操作数（会因数据区导致 desync 漏检），
  改用**逐字节暴力扫描 4 字节位移**（对机器码无对齐要求），命中率高；x86 的 QQMusic.dll
  则搜 4 字节绝对地址。
- 函数边界：解析 x64 `.pdata`（RUNTIME_FUNCTION）得到精确起止。
- 类名还原：x64 由 vtable[-8] 的 `CompleteObjectLocator` → `TypeDescriptor`（`"?AV..."`）。
- 完整 id 表由脚本 `output\逆向\extract_registry.py` 自动产出到 `effect_registry.json`。

## 7. 不确定项 / 未验证

1. `ss_op::init_audio_effect` 的 **"report string"**（由 `0x1800704c0` 用 jsoncpp 解析）具体内容与用途
   未完全厘清——它由引擎以文本形式提供（疑似"打开效果/可编辑效果"列表），与二进制 `.aep`
   是两条并行输入。不影响 §1/§3 的链路结论。
2. `0x1800704c0` 内出现的 3 字节 key（反汇编注解显示为 `"11:"`，实为 Json 异常串中的子串）
   含义未确认。
3. `.aep` root 仅 3 字段，但 `0x1800758c0` 调用了 4 个 schema 子解析器——第 4 个解析器
   （`0x1800768b0`）处理的字段未逐一确认；不影响"逐节点建链"结论。
4. Limiter(6) 追加处的对象/参数细节（阈值等默认值）未提取；仅确认"无条件追加"这一事实。
5. Booleans 上，`Gain` 为线性倍数是**代码证据**（`mulss`）；但 `AmplifierEffect` 是否在别处对
   Gain 再做 dB 显示换算未追踪（不影响 DSP 语义）。
6. 未分析主要导出的完整调用图（如 `qmcpcom_ss_load_aep_set_params` 到 `cfunc_get_aep_config`
   的中间跳转），仅确认了数据流方向。
