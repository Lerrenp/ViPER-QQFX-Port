> 用户向的使用说明见 [../README.md](../README.md)。

## 1. 知识地图

按 **格式层 → 引擎层 → 映射层** 三层组织。每层给结论，细节点链接到对应报告。

### 1.1 格式层：`.aep`（QMAEP）二进制结构

- `.aep` 是 QQ 音乐私有音效文件，魔数 **`QMAEP`**，为 **FlatBuffers 风格的自定义变体**：
  文件起点 `uoffset32 → root table`；root 3 字段 = `magic` 字符串、效果名字符串、`vector<EffectNode>`。
- `EffectNode` 2 字段：`int32 node id`（决定是什么效果）+ `vector<Param>`。
- `Param` 3 字段：`name` 字符串、**value blob**、`unit` 字符串。value blob 的规则很简单：
  `u32 长度 + 原始字节`——**长度 == 4 视为小端 float32 标量**（绝大多数参数），否则按 UTF-8 字符串
  （如 IR 文件名 `irs\xxx.enc`，带结尾 `\0`）。
- table 前有 vtable（`int32 soffset` → `u16 vtable_size, u16 object_size, u16 field_off[]`）；
  字段偏移 0 表示缺省。
- **不能用通用 FlatBuffers 库读**（多一段魔数字符串字段、value blob 形式不同），必须按此 schema 遍历。
  通用解析器见 `tools/aep_parser.py`；逐字节 hex 证据与「全景环绕」首轮解析见
  **[docs/分析报告.md](分析报告.md) §1**。

### 1.2 引擎层：QQ 音效引擎如何加载与处理

分三块理解：**宿主 + DSP 本体 + 资源（IR）**。

- **宿主 `qmcpcom(.dll/x64.dll)`**：负责反序列化 `.aep`、按节点 id 实例化效果对象、组装处理链。
  加载链：`set_effect → set_aep_effect（整读文件）→ set_params → 逐节点 create_effect`。
  关键结论：**实际处理链 = `.aep` 节点序列 + 链尾无条件追加的固定 `Limiter`(id=6)**。
  另有 **76 项插件注册表**（id → 类名 / 构造函数 / vtable），机器可读版见
  [`effect_registry.json`](effect_registry.json)。详见
  **[docs/加载逻辑分析.md](加载逻辑分析.md)**。
- **DSP 本体 `libSuperSound2.dll`**：卷积（IPP FFT）、重采样（SoundTouch）、混响、限幅、EQ/滤波、
  变调、采样器、3D/环绕**全部由它实现**；qmcpcom 的 76 个插件没有把 DSP 下推到别的库。
  各插件内部处理的逐条逆向见 **[docs/DSP内部处理分析.md](DSP内部处理分析.md)**，
  导出面 / 角色 / 卷积分段实现见 **[docs/SS2引擎分析.md](SS2引擎分析.md) §1–§4**。
- **IR（`.enc`）解密算法**：`.enc` = 「裸 WAV 明文 ⊕ 密钥流」的 XOR 流密码；密钥流来自
  `libSuperSound2.dll` 中一张 256 字节常量表（VA 0x1005f788）与二次取模公式：
  `q = (i<=0x7fff) ? i : i%0x7fff`；`index = (q*q + 0x13c1b) & 0xFF`，按 0x80000 字节分块。
  公开仓库的「128 字节循环」只是它在 `i<0x8000` 的近似。详见
  **[docs/IR解密分析.md](IR解密分析.md)**；参考实现 `tools/decrypt_ir.py`。
- **IR 加载语义（`libSuperSound2` 加载器 0x10048c60）**：解密后依次做
  **Trim**（`Trim∈(-96,-30) dB` 时按 `10^(Trim/20)` 阈值从尾部截断）、
  **Fade**（末尾 `Fade` ms 线性淡出，仅 Trim 分支内生效）、
  **重采样到目标采样率**；**无归一化 / 无加窗 / 无去直流**。
  关键实锤：Trim/Fade 对象成员在初始化时**显式清零**（0x10049b47 / 0x10049b3d），
  `.aep` 未携带时 **Trim=Fade=0 → 不生效**；本语料 12 个 IR 全部不激活。
  详见 **[docs/SS2引擎分析.md](SS2引擎分析.md) §2、§6**。

### 1.3 映射层：`.aep` 节点 → V4A 预设

- V4A 预设格式 **schemaVersion 2.1**，24 个效果组按固定顺序排列。分组顺序、每组字段名/类型/range/
  默认值的快照是 [`tools/v4a_schema.json`](../tools/v4a_schema.json)，
  由 `tools/gen_v4a_schema.py` 从 V4A 源码 `EffectGroups.kt` 生成。
  组顺序（`order`）：
  `masterLimiter, playbackGainControl, lufs, fetCompressor, multibandCompressor, ddc,
  spectrumExtension, equalizer, dynamicEq, convolver, fieldSurround, diffSurround, stereoImager,
  headphoneSurround, reverb, dynamicSystem, psychoacousticBass, bass, bassMono, clarity, cure,
  tubeSimulator, analogX, speakerCorrection`。
- **当前映射规则**（实现在 `tools/convert_aep.py` 的 `build()`；规则表同步在
  [../README.md](../README.md) 附录 B）：

  | QQ 节点 | V4A 目标组 | 置信级 |
  |---|---|---|
  | id4 `Amplifier` | `masterLimiter` | verified |
  | id13 `IirEQ10` | `equalizer` | verified |
  | id11 `StereoEnhancer` | `stereoImager` | verified |
  | id12 `Delay`（单边、零反馈） | `diffSurround` | verified |
  | id63 `Mverb` | `reverb` | approx |
  | id2 `StudioIr` | `convolver` | approx |
  | id51/50/33/34/35/24 滤波器 | `dynamicEq` | approx |
  | id57 `SuperBass` | `bass` | approx |
  | 其余节点 | 不映射（skipped） | skipped |

  置信级汇总逻辑见 `_overall_confidence()`：有未映射节点 → `partial`；全部命中且都 verified →
  `verified`；否则 `approx`；零映射 → `skipped`。
- **skipped 名单与原因**：集中在 `convert_aep.py` 的 `SKIP_REASONS` 字典（id → 原因），
  并在 `parsed/*.parse.json` 与 `manifest.json` 的 `unmapped` 字段逐条落地。典型：
  id9 `Exciter`（激励频段与 V4A `spectrumExtension` 不匹配）、id31 `BPFilter`（V4A 无带通类型）、
  id22/15 `HyperBass`（单旋钮 vs 双参数结构不匹配）、id3/5/28 `Chaos/Rotator/PitchShifter`
  （V4A 无时变/变调节点）、id7 `Sampler`、id14/16/18/19 DFX 系列、id21/59 人声、
  id40/55/56/58/60/62/69/70/71/73/74/75 等。判定有据的复核见
  **[docs/范围核查报告.md](范围核查报告.md) §2**。

## 2. 如何新增一个映射规则

以「给 **id9 `Exciter`** 找一个映射」为例（当前结论是 skipped，此处演示**评估流程**；
若评估后仍无合理对应，则应保持 skipped 并补全原因）。

**Step 0 — 先看语料里的真实参数（不要凭类名猜）**

```bash
python tools/aep_parser.py --json aep/001-差分环绕.aep | python -c "import json,sys; d=json.load(sys.stdin); print([n for n in d['nodes'] if n['id']==9])"
# 或直接看该文件的解析 dump：
#   python tools/convert_aep.py aep/001-差分环绕.aep -o out/t.json
#   -> out/t.json.parse.json 的 nodes[] 里有 id9 的全部参数
```

`ExciterEffect` 的参数：`Frequency`（614–1917 Hz）、`Harmonics`（5–10，含小数）、
`MixBack`、`ClipBoost`。**先把全语料 8 处 id9 的取值列成表**，这是判断「能不能映射」的事实基础。

**Step 1 — 查 V4A 侧语义，确认有没有等价物**

- 字段与 range：V4A 源码 `EffectGroups.kt`（`spectrumExtension.strength ∈ [2200,8200]`、
  `exciter ∈ [0,6]`；`clarity.gain ∈ [0,4.5]`）。
- DSP 行为：ViPERDSP 源码（`SpectrumExtension` / `ViPERClarity` 的实现），确认算法结构。
- 对 id9：QQ 激励起始频率 614–1917 Hz **全部低于 V4A 的 2200 Hz 下限**，`Harmonics` 是
  5–10 阶而 V4A `exciter` 是 0–6 无量纲量——**量纲与频段都对不上**，故维持 skipped。
  （此判定已由 [docs/范围核查报告.md](范围核查报告.md) §2.2 复核。）

**Step 2 — 若确认可映射，在 `tools/convert_aep.py` 加分支**

- 在 `build()` 的节点分派里新增 `elif nid == ID_XXX:` 分支（节点 id 常量定义在文件顶部）；
- 数值越界统一走 `_clamp()`，保证有 warning；
- 用 `note(group, CONF_VERIFIED/APPROX, 说明)` 记录决策与置信级；
- 若无对应，宁愿把它加进 `SKIP_REASONS`（写清原因），不要硬凑。

**Step 3 — 重跑批量并校验**

```bash
python tools/batch_convert.py
python tools/validate_preset.py --preset presets/*.json
```

**Step 4 — 同步文档**

- 更新 [../README.md](../README.md) 附录 B 的映射规则表 / 预设一览表；
- 如有结构性结论，在 `docs/` 对应报告里补证据，并更新本文件 §1.3。

**涉及文件清单**

| 文件 | 改动 |
|---|---|
| `tools/convert_aep.py` | 新增/调整映射分支、`SKIP_REASONS`、节点 id 常量 |
| `tools/batch_convert.py` | 一般无需改（仅当新增命名/跳过例外表） |
| `presets/` `parsed/` `manifest.json` | 由 `batch_convert.py` 重新生成（勿手改） |
| `../README.md` | 附录 B 规则表、预设一览表 |
| `docs/开发指南.md` | 本文件 §1.3 规则表 |
| `docs/分析报告.md` 等 | 如有新的源码/DLL 证据则补充 |

## 3. 如何重新生成一切

**依赖顺序**（箭头 = 必须先完成左边）：

```
build_kernels.py  →  batch_convert.py  →  validate_preset.py
（产出 kernels/）    （产出 presets/ parsed/ manifest.json）  （校验 presets/）
```

```bash
pip install -r requirements.txt      # numpy
python tools/build_kernels.py        # 1) 重建 441/ 与 48k/ 两套内核 + kernel_index.json
python tools/batch_convert.py        # 2) 全量转码 -> presets/ parsed/ manifest.json
python tools/validate_preset.py --preset presets/*.json   # 3) 校验
```

要点：

- **`.enc` 缓存**：`build_kernels.py` 把下载的原始加密 IR 缓存在**系统临时目录**
  （`%TEMP%/qqfx_enc`，见 `tempfile.gettempdir()`），缓存命中就不再下载；`.enc` 原文件不纳入仓库。
- **CDN 直链来源**：缺失 `.enc` 的下载直链来自语料元数据 `aep/recommendbase.json` 的
  `effectIRLinks`（字段 `irFileName` / `irLink`），CDN 为腾讯
  `https://dldir1.qq.com/music/clntupate/ss2/irs/<sha1>.enc`。
- **强度顺序不能颠倒**：`batch_convert.py` 依赖 `kernels/kernel_index.json` 把 `convolver.kernelFile`
  指向可读名；内核没先建好，12 个卷积预设就会退化成「找不到内核」。
- `build_kernels.py --hash <sha1>` 支持增量：只重建指定内核，并**合并**进已有
  `kernel_index.json`（不会整表覆盖）。
- 产物 `presets/`、`parsed/`、`manifest.json`、`kernels/` 均为自动生成，**不要手改**。

## 4. 工具清单（`tools/` 8 个脚本）

| 脚本 | 职责（一行） |
|---|---|
| `aep_parser.py` | 通用 `.aep`（QMAEP）解析库：`parse()` 返回 `{magic,name,nodes}`；`--dir` 做全语料 smoke test（节点 id 分布 / 序列种数）。 |
| `parse_aep.py` | 历史脚本：针对「全景环绕」(500) 的带自检断言解析器（原样保留，通用解析请用 `aep_parser.py`）。 |
| `gen_v4a_schema.py` | 从 V4A 源码 `EffectGroups.kt`（+ `CompressorUnits.kt`）提取 24 组 schema，写出 `tools/v4a_schema.json`。 |
| `validate_preset.py` | 独立预设校验器：基于 `v4a_schema.json` 校验组序 / 字段 / 类型 / range / 默认值一致性，不依赖 V4A 源码。 |
| `convert_aep.py` | 单文件转换 CLI：`.aep` → V4A 预设 + `<out>.parse.json`；**全部映射规则与置信级都在这里**。 |
| `batch_convert.py` | 批量转换 CLI：扫 `aep/*.aep` → `presets/*.json` + `parsed/*.parse.json` → `manifest.json`；含跳过/命名例外表。 |
| `build_kernels.py` | 卷积核构建流水线：收集 id2/id7 引用 → 取 `.enc`（缓存/CDN）→ 解密 → Trim/Fade → 4ch 降混 → 双速率重采样 → `kernels/<441|48k>/` + `kernel_index.json`。 |
| `decrypt_ir.py` | QQ `.enc` IR 解密器：内嵌 KEY256 与完整公式（含 0x80000 分块、`i mod 0x7fff`），输出裸 WAV。 |

数据 / 快照文件：`tools/v4a_schema.json`（24 组 V4A 字段快照）、`kernels/kernel_index.json`
（hash ↔ 可读内核名对照，含 roles 与 441/48k 文件名）。
